# 电商售后智能判责引擎（单智能体）—— 简历项目描述

---

## ★ A4 精简版（约半页，直接用）

**电商售后智能判责引擎（单智能体）**　　AI 大模型应用开发

**涉及技术**：Python、LangChain（LCEL / 结构化输出）、Prompt Engineering、DeepSeek、Streamlit

**项目背景**：
售后判责规则密集、资损敏感，人工逐单核对口径不一、成本高。本项目让规则引擎负责判定、LLM 只做语义理解：输入一张售后工单，即输出带依据条款、退款金额与置信度的结构化判定单，结论可复现、可审计。

**项目职责**：

1. 依据消法及平台规则提炼 18 条判责规则，设计 13 层优先级仲裁链，以确定性 return 链保证"同单同判"；
2. 基于 LangChain LCEL 与 `with_structured_output` 构建意图识别链，解析口语化诉求，模型失败自动降级关键词基线并如实标注意图来源；
3. 实现订单状态归并、签收时限与大额阈值拦截；在途订单按退货诉求分流，纯物流查询转人工，不替用户产生资金动作；
4. 咨询分支落地工具调用 Agent：LangChain 1.x 移除 AgentExecutor 后，按迭代上限 / 中间步骤留痕 / 解析错误回灌三个契约手写最小执行器，挂载 4 个只读工具；答复无 decision 字段，引用条款必须来自检索结果，失败显式报错不降级；另建 212 条分层评测集、9 维穷举审计与 Streamlit 判定单界面。

**项目创新点**：

1. **Rule-first**：模型只输出意图与类目，无权产生判定结论，从架构上根除 LLM 判责的不稳定与幻觉；
2. **置信度由判定路径推导**而非模型自评，可复现、可单测；
3. **对抗与降级双兜底**：越权 / 施压话术前置拦截（拦截率 86.7%），语义层故障自动降级且来源透明。

**项目成果**：

1. 语义层在 212 条评测集上准确率 100%、误转人工 0 条；关键词基线 95.8%，可独立兜底；
2. 规则引擎通过 13800 种组合穷举审计，0 违规；修复的 12 项真实缺陷全部转化为回归用例；
3. 系统端到端可运行，具备接入客服工单系统灰度上线的条件。

## 加长版（面试展开 / 备用）

> 定位：AI 大模型应用开发 ｜ 单智能体（规则引擎 + LLM 语义层）

## 项目介绍（3-4 行）

电商售后判责高度依赖人工：客服需逐单核对订单状态、签收时限、类目例外与凭证，判责口径因人而异，误赔与误拒成本高。本项目构建了一个**以规则引擎为主体、LLM 仅做语义理解**的单智能体判责系统：输入一张售后工单，输出带依据条款、退款金额、运费承担方与置信度的**结构化判定单**，全程可复现、可审计、可回归。模型被架构性限制在"意图识别 + 类目判定"两个中间变量上，无权产生判定结论，从根上消除大模型判责的不稳定与幻觉风险。

## 项目职责

**1. 判责规则库建模与优先级仲裁链设计：**
- 依据《消费者权益保护法》第二十五条及平台公开规则，提炼 **18 条判责规则**（七天无理由、例外类目、质量退换、超期拒收、大额复核、幂等拦截、物流争议等），逐条标注出处，构建 `policies.md` 规则库。
- 设计 **13 层优先级仲裁链**（咨询 → 幂等 → 已关闭 → 金额异常 → 大额 → 物流争议 → 例外类目 → 在途/未发货 → 超期 → 质量 → 无理由 → 兜底），以"先到先得"的 return 链实现确定性仲裁，同一工单永远得出同一结论。

**2. 三层架构实现（语义层 / 事实层 / 判定层）：**
- 基于 **LangChain LCEL + `with_structured_output`（function_calling）** 构建意图识别链，将口语化工单（"码大了穿着挤脚退了呗"）解析为枚举意图；模型失败自动降级为关键词基线，界面如实标注意图来源，不伪装成模型输出。
- 实现事实层：订单状态等价类归并（待付款/已取消 → 关闭；派送中/驿站 → 在途）、距签收天数实时计算、例外类目与大额阈值判定，系统固定时间基准避免数据随时间"腐化"。
- 实现"在途订单按退货诉求分流"等关键分支：纯物流查询一律转人工，**不替用户产生任何资金/账务动作**。

**3. 评测体系与不变量审计：**
- 构建 **212 条分层评测集**（150 条 silver 自动标注 + 62 条人工精标，含 15 条对抗样本、9 条边界样本、8 条口语化样本）。
- 编写**穷举式矩阵审计脚本**，对订单状态 × 意图 × 天数 × 金额 × 类目 × 凭证等 9 个维度共 **13800 种组合**做不变量断言（如"退款金额不得超过实付""例外类目不得误判支持无理由"），0 违规。

**4. 判定单可视化前端：**
- 开发 Streamlit 判定单界面：依据条款可展开规则原文、决策 trace 逐条展示 13 层规则的命中情况、原始 JSON 附不变量校验结果；订单与用户诉求硬绑定（诉求只能从该订单的真实历史工单中选择），杜绝"订单 A + 订单 B 诉求"的虚假组合。

## 项目创新点

**1. Rule-first 架构：模型"说话"，规则"拍板"。**
大模型不产生 `decision` 字段，只输出意图与类目两个中间变量；结论由确定性规则引擎按优先级计算。判定单可复现、可单测、可对账——这是把 LLM 用在"规则密集 + 资损敏感"场景的关键取舍。

**2. 置信度由判定路径推导，而非模型自评。**
规则唯一命中 0.95、转人工不标置信度（系统确定的是"需要人工"而非"结论正确"），避免大模型自信过头的误读，也使置信度可回归测试。

**3. 穷举矩阵审计代替抽样测试。**
不做"跑几条看看"，而是把 9 个状态维度穷举成 13800 组合，用不变量断言机器化验证——任何一次规则改动都能在秒级完成全量回归。

**4. 对抗鲁棒性显式设计。**
针对"冒充内部员工要求跳过流程""不退就 12315 投诉"等越权/施压话术设置前置拦截；对抗样本拦截率 86.7%，越权话术一律转人工而非放行。

**5. 降级可观测。**
语义层失败自动回退关键词基线，判定单上如实标注意图来源（语义层 / 关键词降级及原因），系统"什么时候在用模型、什么时候没在用"对使用者完全透明。

## 项目成果

1. **语义层准确率 100%（212/212）**，误转人工 0 条；关键词基线 95.8%，作为模型故障时的降级兜底仍然可用。
2. **规则引擎在 13800 种组合的穷举审计下 0 违规**，gold 精标集 17/17 通过。
3. 识别并修复 12 项真实缺陷（在途分支不看诉求导致资损、0 元订单判出 0.00 元退款、越权话术被放行等），全部沉淀为失败模式清单与回归用例。
4. 交付可运行的端到端系统（一键启动 / 停止 / 状态自查脚本 + 212 条评测 + 三份文档），同一输入永远得到同一张判定单，具备直接接入客服工单系统做灰度的条件。

### 面试口径提醒（不写进简历）

- 被问"为什么不是多智能体"：判责是规则密集的确定性任务，用规则引擎 + 优先级仲裁链比多智能体协商更可靠；需要自主规划的是咨询分支，且已单独落地（4 个只读工具、≤6 步循环、引用必须来自检索结果、失败显式报错、答复无 `decision` 字段），没有让 Agent 碰判定。注意口径：LangChain 1.x 已移除 `AgentExecutor`，官方替代是 `create_agent`；咨询执行器是按三个契约手写的，不要说"基于 AgentExecutor"。
- 咨询专项的 33/33 只说"**工具调用与引用可验证性 100%**"，不说"答复准确率 100%"；引用精确度另报，过度引用是已知限制。
- 被问数据来源：规则引自消法与平台公开规则并逐条标注；订单按场景矩阵构造；评测语料为人工编写 + 公开法规/平台规则改写，未抓取投诉站原文——关键说清构造方法与许可，而非声称生产数据。
- 不要写"准确率 100%"不加限定词，永远带上"212 条评测集上"。
